On this page

讲故事 ​

我曾经加入了一个大型 Minecraft 服务器，里面有各种 Boss 战和修仙系统什么的可以玩，但是由于加的 mod 太多，随着服务器进程推进，隔三岔五就会出现一些冲突、Bug，我们的腐竹只得不断地更新那个 QQ 文件夹，让成员们一次次的下载。服务器开了正版验证，这让一部分玩家无法加入，于是腐竹关掉了正版验证，但正版玩家们又开始抱怨新的皮肤插件难用……最后我被这些事情烦恼得放弃了这个服务器。

不过，从那之后我被学业和代码占用了所有时间，也确实没有玩游戏的时间了，当然也就没有资格去指摘那位腐竹。不过，当时服务器的混乱还是在我的心里留下了深刻印象。

开牡蛎 ​

我自己也曾是一名腐竹，所以那之后我常常揣摩着怎么解决这些问题，它们在我这个“牡蛎”里留的时间也挺久了。有一天，我决定把它们撬出来，于是 Syncraft 的编写工程提上了日程。

文件同步 ​

如果说服务器需要不断地更新，不管这些更新是小修复还是玩法大改，本质都是让服务器成员下载那些更新包，塞进自己的游戏里。如果启动器能够完成这些任务，为什么还需要腐竹们一遍遍地教呢？文件同步作为 Syncraft 的第一个功能，也是它名字的由来（synchronous + craft）。

内置身份验证服务 ​

安全是其次，皮肤更是一件至关重要的事情！在不用正版验证的情况下怎么做才好呢？如果是生电/原版服，硬要求成员安装皮肤 mod 也不现实；Skinrestorer 么……我甚至专门写过文章来教人怎么用诶……

那么就用自己的验证服务吧！Syncraft 会自动为客户端配置 authlib-injector ，并使用 Syncraft 服务端内置的 yggdrasil 服务。当它的身份伪造关闭时，只有在 Syncraft 服务端经过邮箱注册和身份验证的玩家才能加入，保证了安全；当身份伪造打开时，所有玩家均可以加入，但皮肤依然会从 Syncraft 到 Mojang 到 Littleskin 层层 fallback ，保证了正版玩家和在 Syncraft 注册的玩家都依然能用到自己的皮肤。

服务器版本管理 ​

在 Minecraft 服务器目录里建一个 Git 仓库吧，一切都会好起来的！通过对 Git 的文件差异对比和提交信息的使用，Syncraft 可以帮助腐竹们管理服务器更新，并及时通知客户端。

展望 ​

写 Syncraft 的另一个理由是，随着机械动力：航空学和各种地形生成 mod 的推出，我对于有剧情并实时更新的大事件驱动服务器有了一些不切实际的遐想──为什么不能把 Minecraft 打造成一种“原神”呢？
